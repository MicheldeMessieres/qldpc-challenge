# [[420,8,13]] — weight-5 bivariate bicycle code from arXiv:2610.06623v1 Table 3

## Direction & hypothesis

Target: the `unrestricted` x `weight-6` CSS cell. arXiv:2610.06623v1
(Cruz-Benito, "Large Language Model-Guided Discovery of Weight-Five
Bivariate Bicycle Codes") catalogues 1,142 weight-five BB presentations in
630 colored-BLISS classes. This row, the paper's class `CL-4a95cc39`,
originally carried a decisive upper endpoint supported only by a stored
BP-OSD-family scalar (no persisted witness) — the single most
failure-prone evidence tier the author's own prior tracking has seen on
this catalogue (most audited rows of that tier lost 30-60% of their claimed
distance once an independent search was run against them). A prior,
private hardening pass already replaced that scalar with an explicit,
independently reconstructed and re-verified weight-13 logical operator on
each side. This submission carries that already-hardened result to the
board, re-deriving the check matrices from scratch in this PR rather than
reusing anything not committed here.

## What was searched

No fresh search for this PR. Direct re-verification of one already-hardened,
already-published presentation: `l = 15`, `m = 14`, `A = 1 + y^3`,
`B = 1 + x y^3 + x^4`, so `n = 2*15*14 = 420`.

The check matrices were rebuilt from these polynomials with
`research/kit/bb.py:build_bb` and `k` was independently re-derived as
`n - rank(H_X) - rank(H_Z)` over GF(2), reproducing the paper's `k = 8`
exactly.

## Evidence trail

- Rebuilt and measured: `n = 420`, `k = 8`, max check weight 5, one
  connected component (no replicated decomposition — confirmed
  structurally on the rebuilt matrices).
- The paper's own catalogue originally recorded only a raw decoder scalar
  as the upper bound for this row (lower bound `d >= 5` from exhaustive
  weight-four exclusion). A prior, private randomized search over the
  kernel of the opposite check matrix (random column permutations each
  trial, keeping the lightest rows and their pairwise GF(2) combinations
  under a fresh RREF) found an explicit weight-13 logical operator on each
  side: zero syndrome against the opposite check matrix, outside the
  stabilizer row space, re-confirmed by a second, separately coded
  exclusion check.
- This PR independently re-derives `H_X`/`H_Z` from the published
  polynomials from scratch with `research/kit/bb.py`, re-checks both
  witnesses' commutation (zero syndrome) and row-space exclusion directly
  against these freshly rebuilt matrices, and re-confirms `k = 8` — a clean
  rebuild against this repository's own construction tool, not a copy of
  unreviewed matrices.
- The paper prints a second, BLISS-confirmed non-isomorphic `(15,14)`
  presentation at the same `[[420,8,13]]` point (class `CL-d192c3d1`,
  `A = 1 + y^5`, `B = 1 + x^6 + x^8 y^5`), hardened to `d <= 13` by the same
  prior pass. It is **not** filed as a separate board entry here: it ties
  this entry's point exactly and would not advance any new frontier cell,
  matching how this project's already-merged `[[420,4,22]]` entry handled
  its own second (possibly-isomorphic) class.
- Submitted as a witness-backed **upper bound**, `d <= 13`, on both sides.
  It is not certified exact and is not described as such.
- `uv run python verify/qldpc_verify.py codes/420-8-13.json` passes locally
  with `ok: true`, `earned_distance.d = {value: 13, tier: upper_bound}`, and
  one connected `css_equivalent` image. A full-board
  `verify/verify_all.py` pass found no fingerprint or signature collision
  with any existing entry.

## Dead ends

None for this row directly in this PR — the hardening work (collapsing the
raw decoder scalar to a verified witness) was done in a prior private pass,
not here. That pass's own history is worth recording: an early version of
the same search combined two logical-flagged rows from the same coset
without re-checking that their XOR was still outside the stabilizer row
space, which can produce a spuriously light invalid candidate when the two
rows are representatives of the same logical coset. The version that
produced this witness re-verifies every combined candidate before accepting
it, and this PR re-verifies the final result again from scratch.

## Tools

Human-directed agent work (Claude Code, Claude Opus/Sonnet 5) rebuilding
and re-verifying an already-hardened, published construction, using
`research/kit/bb.py` for construction and `verify/qldpc_verify.py` for the
local gate. The witness itself was produced in an earlier, private pass by
the randomized kernel/permutation method described above; the method is
specified in full so it can be rewritten directly against
`research/kit/bb.py`'s matrices.

## Reproduction

```python
import sys; sys.path[:0] = ["research/kit"]
from bb import build_bb
HX, HZ = build_bb(15, 14, [(0, 3), (0, 0)], [(1, 3), (4, 0), (0, 0)])
```

Terms are `(x, y)` exponent pairs against `F_2[x,y]/(x^15 - 1, y^14 - 1)`;
`H_X = [A|B]`, `H_Z = [B^T|A^T]` per `research/kit/bb.py`. Source of the
presentation: arXiv:2610.06623v1, Table 3, class `CL-4a95cc39`.

Juan Cruz-Benito (@cbjuan).
