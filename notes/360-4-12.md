# [[360,4,12]] — non-CSS perturbed bivariate bicycle (PBB) code, witness-backed upper bound

**Paper:** arXiv:2610.06623, "Large Language Model-Guided Discovery of
Weight-Five Bivariate Bicycle Codes" (presentation `PL-28c4edd8`).

## Direction & hypothesis

Target: the general-stabilizer board's `unrestricted` x `weight-6` (and
looser) cells. Same PBB construction family as the companion submissions in
this batch (block-1 z-part `[C | D]` added to a CSS bivariate-bicycle
stabilizer matrix: `H = (A B | C D; 0 0 | B^T A^T)`).

Unlike the companion `[[48,4,4]]`, `[[144,4,8]]`, `[[180,2,11]]`, and
`[[216,4,10]]` submissions in this batch, **this one is not exact in the
source repository either** -- it is included because its witness-backed
upper bound held up under this board's own independent re-verification, and
it is honestly reported as `upper_bound` throughout.

## What was searched

Source: a weight-5-targeted LLM-guided evolutionary search (OpenEvolve,
"pbb-large" campaign) over 4-tuples `(A, B, C, D)` at `(ell=15, m=12)`,
screened by `k`, isotropy, the combined non-CSS gate
(`evaluation/noncss_gate.py`), and a BP-OSD distance estimate. This is a
direct (non-component), connected presentation.

Distance evidence in the source repository
(`results/weight5_publication_catalogue.jsonl`, `distance_class`):
`status_code: "C"` (certified interval, not exact) -- a certified **lower**
bound of 5 (method `L4`, exhaustive exclusion of weight-<=4 logicals) and an
**upper** bound of 12 supported by both a BP-OSD decoder find (method `B`)
and a MILP incumbent (method `I`, feasible solution at weight 12, not proven
optimal within budget).

## Evidence trail

`(ell, m) = (15, 12)`, `A = 1 + x^4y`, `B = 1 + xy^6 + x^2`, perturbation
`C = 0`, `D = 1 + x^2` (0-indexed exponent pairs: `A=[[0,0],[4,1]]`,
`B=[[0,0],[1,6],[2,0]]`, `C=[]`, `D=[[0,0],[2,0]]`).
`n = 2·15·12 = 360`, `k = 4`, max check weight 5.

- Source repo's evidence: lower bound 5 (certified exact-exclusion),
  upper bound 12 (BP-OSD + MILP-incumbent, not proven optimal).
- Independent re-verification in *this* repository: rebuilt the symplectic
  check matrix via `evaluation/pbb_code.py:build_pbb_code`, then ran this
  repo's own `cli/qldpc.py submit --dry-run` (RIS search, 20,000 trials,
  `gf2_fast` accelerator at 1,000,000 trials). **Independently found
  d<=12**, matching the source's upper bound -- i.e. an independent search
  of a different kind (random information set, not BP-OSD or MILP) did not
  find anything lighter either, which is modest additional corroboration
  but still not an exactness proof.

Final claim here, honestly: `upper_bound`, `d<=12`. This is the weakest
evidence tier among this batch's submissions, included because it survived
an additional, independent search rather than because it is exact.
