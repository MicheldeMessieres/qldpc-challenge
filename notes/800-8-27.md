# [[800,8,27]] — the board's single-layer B = 3 weight-8 tile code at 20 x 20

## Direction & hypothesis

The single-layer (radius <= 4) weight-8 CSS cell is led by the B = 3 tile code of codes/288-8-15.json and
codes/338-8-16.json (@fullymiddleaged; tile family of Steffan, Choe, Breuckmann, Pereira, Eberhardt,
arXiv:2504.09171) and its grafted reductions codes/316-8-16.json and codes/280-8-15.json (@dorakingx).
notes/338-8-16.md records that the tile screen stopped at n <= 400. We measured how the distance of the same
bulk tile grows with lattice size and found about 1.5 per lattice step, so kd^2/n rises with n up to the
n <= 1000 cap. Derived from codes/338-8-16.json by @fullymiddleaged. This entry is that same tile at a larger size; it is not a new construction. Our contribution: only the 20 x 20 instance, its single-layer layout and its distance evidence.

## What was searched

- The same bulk tile (X-tile {h00,h01,h11,h22,v02,v10,v20,v21}, Z-tile by T2), built with the repository's
  open directional boundary research/local2d/planar.build_open_directional(L, L, S_f, S_g) with
  S_f = {(0,0),(0,1),(1,1),(2,2)}, S_g = {(0,2),(1,0),(2,0),(2,1)}, for L = 12..22.
  The boundary rows differ from those of codes/288-8-15.json; at 12 x 12 both give [[288,8,15]].
- Distance ladder (two-side RIS, verify/gf2_fast.cpp built locally, pair depth 8):
  L=16: 20, L=17: 21, L=18: 23, L=19: 25, L=20: 27, L=21: 28, L=22: 30 (6-8 seeds x 100k trials each).

## Evidence trail

- One-side searches (4 seeds x 100k trials per side) give the stored X and Z witnesses.
- Deep pass: 5600000 RIS trials in total over fresh seeds, about 1.45 CPU-hours; lightest found = 27.

| CPU-hours searched | lightest logical found |

| 0.19 | 27 |

- Calibration control at the same depth: codes/968-8-23.json (flagship planar BB, 22 x 22) — the search
  recovers its weight-23 Z witness in 5 of 6 seeds, where a 3k-trial search had reported 26.
- Claim: witness-backed upper bound d <= 27. Not exact; no lower bound is claimed.

## Dead ends

- Our attempt to find a better single-layer pattern on triangular / honeycomb site lattices (about 52,000
  weight-6 and 15,800 weight-8 tile patterns) found nothing above the existing families; for every good pattern
  k equals the mixed area of the two tile halves, which the radius cap bounds.
- The weight-6 flagship family (codes/968-8-23.json) grows only about 1 per lattice step, so it does not
  gain from size the way this tile does.

## Tools

Claude Opus 5.5 (Claude Code); repository research/local2d/planar.py (builder), verify/gf2_fast.cpp (RIS),
verify/qldpc_verify.py and verify/validate_candidate.py. Approximate compute: see provenance.notes.

## Reproduction

planar.build_open_directional(L, L, S_f, S_g, S_fbar=-S_f, S_gbar=-S_g) with the supports above; layout
A(i,j) -> (-i-j, j-i), B(i,j) -> (-i-j, j-i+1) on the integer grid (radius 4.000, spacing 1).
